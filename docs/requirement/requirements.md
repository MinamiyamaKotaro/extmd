# 要件定義書: extmd

## 1. 概要

Excelファイル（.xlsx）を入力として受け取り、Markdownファイルに変換するCLIツール。
使用言語は Rust。

最大の特徴は、いわゆる「Excel方眼紙」（セルを方眼紙のマス目のように極small幅で使い、
1つの文字列が複数セルにまたがって視覚的にはみ出して表示されているシート）を正しく扱うこと。
このようなシートをそのまま単純にセル単位でMarkdownテーブル化すると、
1文字ずつバラバラのセルに分割された意味不明な表になってしまう。
本ツールは、セルからはみ出している文字列を検出し、それらを1つの論理的なブロック
（見出し・段落・表のセルなど）として結合してから変換する。

## 2. 背景・課題

- 日本の商習慣では、Excelを表計算ソフトとしてではなく「方眼紙」的なレイアウトツールとして
  使うケース（申請書・仕様書・議事録テンプレート等）が非常に多い。
- このようなファイルをそのままMarkdownやCSVに変換すると、1マス＝1セルとして扱われ、
  文章がセルごとにブツ切りになり可読性が失われる。
- 実際のExcelの挙動では、あるセルに文字列を入力した際、右隣のセルが空である限り
  文字列は右方向にはみ出して表示される（セルの値としては元のセルのみに格納されている）。
  この「見た目のはみ出し」を再現的に検出し、論理的に1つのセル/テキストブロックとして
  扱うことが本ツールの中核要件となる。

## 3. 用語

| 用語 | 定義 |
|---|---|
| 方眼紙Excel | 行の高さ・列の幅を均一・小さくし、罫線でマス目状にしたExcelシート。文書やフォームのレイアウトに使われる |
| はみ出し（オーバーフロー） | セルに入力された文字列が、セル幅を超えて隣接する空セル上に視覚的に表示される現象 |
| 論理セル / ブロック | はみ出しや結合セルを考慮して再構成した、意味のある1つのテキスト単位 |
| ネイティブ結合セル | Excelの「セルの結合」機能で明示的に結合されたセル範囲 |

## 4. スコープ

### 4.1 対象とする範囲（v1）

- 入力ファイル形式: `.xlsx`（Excel 2007以降形式）
- 1ファイル内の全シート、またはオプションで指定したシートのみを変換
- セルのはみ出し検出とブロック結合
- ネイティブ結合セルの認識
- 結果をMarkdown（見出し・段落・テーブル）として出力
- CLIとしての基本的な引数・オプション処理

### 4.2 対象外（v1では扱わない）

- `.xls`（旧バイナリ形式）、`.xlsb`、`.ods` などの他形式（将来拡張の可能性はあり）
- グラフ・画像・図形（テキストボックス、SmartArt等）の抽出
- セルの数式評価結果以外（数式そのものの変換・再現）は対象外。値として保存されている計算結果を使用する
- 条件付き書式、データ検証等の再現
- セルの上下方向（縦方向）のはみ出し（改行なしで行の高さを超える場合）は将来検討事項とし、v1は横方向のはみ出しのみを対象とする
- 双方向（右揃えセルが左方向にはみ出すケース）は将来検討事項とし、v1は左揃え・左から右方向のはみ出しのみを対象とする

## 5. 機能要件

### 5.1 CLI仕様（案）

```
extmd <INPUT.xlsx> [OPTIONS]

引数:
  <INPUT.xlsx>          変換対象のExcelファイル

オプション:
  -o, --output <PATH>   出力先ファイル or ディレクトリ（未指定時は標準出力 or 入力名ベース）
  -s, --sheet <NAME>    変換対象シート名を指定（複数指定可、未指定時は全シート）
  --strategy <NAME>     解析戦略を指定（auto | grid-paper | tabular、デフォルトはauto）
  --overflow-threshold <N>
                        はみ出し判定の感度調整用パラメータ（後述、デフォルト値をドキュメント化）
  --no-overflow-merge   はみ出し結合を無効化し、セル単位そのままで変換（--strategy tabular の別名）
  -v, --verbose         詳細ログ出力
```

※オプション名・デフォルト値は設計フェーズで確定する。ここでは方向性のみ定義。
※解析ルールはRustのtraitによるStrategyパターンでドメインごとに切り替え可能な設計とする。
  詳細は[アーキテクチャ設計書](../design/architecture.md)を参照。

### 5.2 入力

- ローカルファイルパスで指定された `.xlsx` ファイルを読み込む
- 存在しない/破損している/非対応形式の場合は、エラーメッセージを表示して終了する

### 5.3 変換ロジック

#### 5.3.1 セル情報の取得

各セルについて、変換に必要な以下の情報を取得する。

- セル値（文字列 / 数値 / 日付 / 真偽値、数式の場合は計算済みの値）
- セルの座標（行・列）
- 列幅・行高
- 折り返し設定（wrap text）の有無
- 文字揃え（左揃え / 中央揃え / 右揃え）
- ネイティブ結合セルの範囲情報
- フォントサイズ・太字などの書式（見出し判定に利用）

#### 5.3.2 はみ出し検出ロジック（v1ヒューリスティック）

以下の条件を満たす場合、対象セルの文字列は右方向にはみ出していると判定する。

1. セルに文字列が入力されている
2. `wrap text` が無効である（有効な場合、Excel上ではセル内で折り返されるためはみ出さない）
3. セルの推定描画幅（文字数・全角/半角を考慮した概算幅）が、そのセル自身の列幅より大きい
4. 右隣のセルが空である

上記を満たす場合、右隣のセルへ向けてはみ出しが継続すると仮定し、
「推定描画幅を使い切るまで」または「空でないセルに到達するまで」の間、
右隣の空セル群を対象セルと同一の論理ブロックとして結合する。

この判定はExcelの実際のレンダリング（フォントメトリクス・DPI・ズーム等に依存）を
完全に再現するものではなく、近似的なヒューリスティックであることに留意する。
判定の精度は実データでの検証を経てチューニングする。

#### 5.3.3 ネイティブ結合セルの扱い

- Excelの「セルの結合」で明示的に結合されている範囲は、そのまま1つの論理ブロックとして扱う
- 結合セル内ではみ出し判定は行わない（結合範囲自体がすでに1ブロックのため）

#### 5.3.4 ブロックからMarkdownへの変換方針

- はみ出し結合やネイティブ結合によって再構成した論理ブロックの並びを行ごとに評価する
- 1行が単一の大きなテキストブロックで構成される場合（方眼紙の文章行など）は、
  段落テキスト（フォントサイズ・太字等の情報があれば見出しレベル `#`〜`######` 等）として出力する
- 複数列にわたり規則的にセルが埋まっている領域（通常の表形式データ）は、
  Markdownのパイプテーブル（`| a | b |`）として出力する
- 上記の判定基準（何をもって「表」とみなすか）は設計フェーズで詳細化する

### 5.4 出力

- 変換結果はMarkdown（`.md`）として、指定パス or 標準出力に書き出す
- 複数シートを変換する場合の出力形態（シートごとに別ファイル か 1ファイルに見出しで連結）は
  オプションで選択可能とする（デフォルト方針は設計フェーズで確定）

## 6. 非機能要件

- 動作環境: macOS / Linux / Windows（クロスプラットフォーム）
- 実用的なファイルサイズ（数千〜数万セル規模）を許容できる処理時間で変換できること
- 外部ネットワーク通信を行わない（ローカル完結処理）
- エラー発生時は原因が特定しやすいメッセージを出力すること

## 7. 技術スタック候補

- 言語: Rust
- Excel読み込みライブラリ候補:
  - `calamine`: 純Rust実装、`.xlsx`/`.xls`/`.xlsb`/`.ods`対応、読み取り専用。実績が多く高速だが、
    列幅・折り返し設定などスタイル情報の取得可否は要検証。
  - `umya-spreadsheet`: `.xlsx`向け、読み書き両対応でスタイル情報（列幅・フォント・結合セル等）を
    比較的詳細に取得可能。はみ出し判定にはスタイル情報が必須のため有力候補。
  - → はみ出し判定に必要な情報（列幅・wrap text・フォント）が取得できるかを設計フェーズで検証し、
    最終的なライブラリを決定する。
- CLI引数パース: `clap`
- テスト: 実際の方眼紙Excelサンプルを用いたスナップショットテスト

## 8. 前提・要確認事項（オープンクエスチョン）

実装に進む前に、以下は利用者側での確認・意思決定が必要な項目。

1. **はみ出し判定の精度をどこまで求めるか**: 完全再現は困難なため、ヒューリスティックの
   誤検出（結合すべきでない箇所を結合、または逆）をどの程度許容するか。
2. **表形式データとの共存**: 1ファイル内に「方眼紙的な文書パート」と「通常の集計表パート」が
   混在する場合の判定方針（フォールバック・手動指定オプションの要否）。
   → [アーキテクチャ設計書 6章](../design/architecture.md#6-戦略の選択strategyselector)
   でシート単位に解析戦略（Strategy）を自動選択/明示指定する方針を提示。
   `affinity` のスコアリング詳細は未確定。
3. **出力の粒度**: 複数シートを1つのMarkdownにまとめるか、シートごとに分割するかのデフォルト。
4. **見出しレベルの判定基準**: フォントサイズ・太字のどの組み合わせを `#`〜`######` に
   マッピングするか。
5. **対応バージョン範囲**: `.xls`（旧形式）対応の要否と優先度。
6. **CLIオプション名・デフォルト値**: 上記5.1は暫定案であり、確定させる必要がある。
